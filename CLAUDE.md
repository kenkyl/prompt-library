# CLAUDE.md

Operating context for this repo. Loaded automatically every session.

## What this is

One canonical file per prompt, compiled into the surfaces Claude actually reads,
behind a gate that makes sensitive content structurally unable to reach a commit.
The repo is **public**; real values live in a gitignored overlay and are merged in
at build time. `README.md` explains the design; `CHANGELOG.md` has history and the
current known gaps.

## Invariants — do not break these

- **`prompts/` and `references/` have exactly one writer: the user.** No command
  writes there. Imports land in `inbox/staged/`; `build` writes `build/`; `install`
  writes outside the repo. `promote` refuses to overwrite an existing file.
- **`build/` and `private/` are gitignored unconditionally.** Rendered output
  contains overlay values by design, so "committed files never contain overlay
  content" is a property of the layout, not a flag.
- **Frontmatter is the variable contract; `.env` holds only values.**
  `env/*.env.example` is generated — never hand-edit it. `check` set-compares
  `{{VAR}}` tokens against `vars:` declarations in both directions.
- **No dependencies, targeting Python 3.9.** `/usr/bin/python3` is 3.9.6 with
  neither PyYAML nor `tomllib`. That is why `lib/frontmatter.py` vendors a
  restricted-YAML reader. Adding a dependency means a venv, which breaks
  `./bin/prompt` on a fresh clone. Do not "simplify" this.
- **Builds are byte-reproducible.** The managed marker carries no timestamp, so
  `diff -r` between two builds means "the templates differ" and nothing else. Two
  separate bugs came from breaking this; don't reintroduce a volatile field.
- **`scan/allow.txt` cannot suppress denylist hits, only pattern families.** An
  allow entry naming a customer would publish the term the denylist exists to hide.

## Commands

```
./bin/prompt list | show | check | build | install | package | fill | env
                  | init | new | scan | doctor
```

Always `./bin/prompt`, never `python3 bin/prompt` — the user's shell aliases
`python3` to a nonexistent `python3.11`. Shebangs ignore aliases.

`check` before committing. `doctor --fix` after cloning (sets `core.hooksPath`).
`WALKTHROUGH.md` is a copy-pasteable by-hand test pass over every verb.

## Facts that cost live failures to learn

None of these are in any documentation. Each was found by a real run going wrong.

- **`~/.claude/skills/` is interactive only.** A scheduled task resolves skills from
  the account catalog and cannot see it. Worse: a task told to run a skill absent
  from that catalog **does not fail** — it picks the closest name it can see and
  proceeds. One run executed a different skill entirely and produced output. So
  "the task ran and produced something" is not evidence it ran your prompt.
- **`~/Claude/Scheduled/<name>/SKILL.md` is generated by the desktop app**, not read
  by it. Writing there produces a directory the app never recognises as a task. A
  `scheduled:` frontmatter key existed briefly for this and was wrong.
- **A skill that names a knowledge file it doesn't carry will find the wrong one.**
  A run searched Drive, found an older copy of the same spec, and read it without
  complaint. `reference:` bundles the doc into `skills/<id>/references/`, and the
  generated pointer both names the relative path **and forbids searching
  elsewhere**. Naming the path is only half the fix.
- **Account-catalog caps differ from Claude Code's.** `description` ≤ 1024 and
  `name` ≤ 64 chars, lowercase/digits/hyphens, no `anthropic`/`claude`. Documented
  at platform.claude.com. The Help Center says 200 for description; that is wrong.
- **The local `~/.claude/skills/synced/` mirror lags the cloud by hours.** Do not
  build a reachability check on it — it reports correctly-published skills as
  missing. `distribute: account` drives a reminder, never an assertion.

## Conventions

- `{{NAME}}`, uppercase only. `{{{{` escapes a literal `{{`. `$ARGUMENTS` and `$1`
  are reserved — the compiler emits them; declare `from-arg:` instead.
- `{{#IF_X}}` … `{{/IF_X}}`, block style only, both tags alone on their lines. One
  construct, no else, no nesting. Put an optional section **last** so numbering
  stays contiguous when it drops.
- `surfaces:` is what gets **built**. `distribute:` is where it must **land** to be
  reachable. Different axes — conflating them shipped an install target that wrote
  files nothing read.
- Sensitive-but-load-bearing content becomes a `private: true` variable resolved
  from `private/` via `@file`, with a committed `env/fragments/*.example.md` showing
  the shape. **Never an alternate body** — that recreates the duplication bug.
- Placeholders in committed example fragments avoid matching the gate's own
  patterns (`<like-this>`, no currency symbols, no `__c` suffixes) so the gate stays
  armed on those paths instead of being suppressed by an allow rule.
